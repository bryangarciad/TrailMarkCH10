# Challenge 3.1: Sync You Can See

**Course 3 · Class 3.1 (WatchConnectivity) · 100 pts · iOS + watchOS**

Pocket sync works now: record a memo on the watch and it shows up on the phone.
From the wrist, though, you can't tell whether it worked. Did the memo leave?
Is it still queued? Did the phone's numbers ever make it over?

In this challenge you make sync **visible**, and you add a second kind of payload.
Each part uses a different transfer type from class, so pick the one that fits
each payload.

> Starting point: branch `mdi-113-class-2`. Create your own branch from it.
> Everything you need is already in `ConnectivityManager`. You're extending it,
> not replacing it.

---

## Part 1: "iPhone Today" on the wrist (25 pts)

The phone already calls `model.mirrorTodayToWatch()` after it refreshes Health data.
Nothing on the watch reads it yet.

**Build**

- In `WristHomeView`, add a second card under the step count titled **"iPhone Today"**.
  It shows steps and distance from `model.connectivity.mirroredSummary`.
- Show how old the data is, e.g. *"updated 4 min ago"*. `ActivitySummary.date` is set
  when the phone builds the summary. Look at `Text(_:style: .relative)`.
- If nothing has arrived yet (`nil`), show a short placeholder such as
  *"Open TrailMark on your iPhone"* instead of zeros.

**Think about it:** the phone may call `mirrorTodayToWatch()` many times while the
watch is asleep. How many of those values does the watch receive when it wakes, and
why is that the behavior you want here?

## Part 2: Quick Log from the wrist (25 pts)

Session 3.2 adds real workout sessions. Until then there's no way to send an
*activity* from the watch. Add a manual one.

**Build**

- New watch screen `Views/QuickLogView.swift`, linked from the watch menu as **"Quick Log"**.
- Let the user pick a duration (5 to 60 minutes, in steps of 5) and tap **Log**.
- Build a `WorkoutRecord` that **ends now** and started that many minutes ago.
  Estimate `distanceMeters` from a walking pace of about 80 m/min.
- Send it with the hook that already exists in `WatchModel`. **Do not** add a new send
  method to `ConnectivityManager`.
- Give the user feedback after logging (a confirmation label, or dismiss the screen).

**Verify:** with the **iPhone app force-quit**, log an activity on the watch. Then open
the phone app. The activity must be in the **Journeys** tab.

**Think about it:** which transfer type did your record travel on, and what would have
happened with `sendMessage` in that force-quit test?

## Part 3: Sync status on every memo (35 pts)

Right now `transfer(memo:fileURL:)` is fire-and-forget. Make the queue visible.

**Build in `ConnectivityManager`**

- A published `pendingMemoIDs: Set<UUID>`. Insert the memo's ID when you start a file
  transfer. Put the ID in the transfer's metadata too (you'll need it back).
- A published `pendingRecordCount: Int` for queued userInfo records (workouts and journeys).
- Implement the **sender-side** completion callbacks and update the state from them:
  - `session(_:didFinish fileTransfer:error:)`
  - `session(_:didFinish userInfoTransfer:error:)`
  - On error, keep the item pending and set `lastError`.
- **The queue survives relaunch.** After activation completes, rebuild both values from
  `session.outstandingFileTransfers` and `session.outstandingUserInfoTransfers`.
  Otherwise a memo queued before the watch app was killed shows as "synced" when it isn't.

**Build in the watch UI**

- In `WristMemoView`, each memo row shows a small status icon:
  - pending: `arrow.triangle.2.circlepath` (secondary color)
  - delivered: `checkmark.circle.fill` (green)
- Under the Record button, show *"2 items waiting for iPhone"* while anything is
  pending, and show `lastError` if there is one.

**Gotchas**

- The delegate runs on a background queue, and `WCSessionFileTransfer` isn't `Sendable`.
  Pull the values you need out of it **before** hopping to the MainActor. Look at how
  `session(_:didReceive:)` handles `file.metadata`.
- The completion callbacks fire on the **sender**. The phone never calls them for memos
  coming from the watch.

## Testing setup

- Use a **paired** iPhone + Apple Watch simulator pair (Xcode ▸ Window ▸ Devices and
  Simulators), or real devices. A lone iPhone simulator reports `isPaired == false`, so
  `ConnectivityManager` skips every send on purpose.
- Run the watch scheme and the iOS scheme both at least once so each app is installed.
- On simulators, file transfers can take several seconds. That wait is a good time to
  watch your pending icon.
